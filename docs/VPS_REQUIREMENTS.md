# Требования к VPS

## Короткая рекомендация

Для нескольких личных устройств достаточно чистого Linux VPS:

```text
CPU:       1 vCPU
RAM:       512 MiB–1 GiB
Disk:      5 GiB+
Network:   публичный IPv4 или IPv6, стабильный канал
Access:    SSH с root или passwordless sudo
Firewall:  TCP 22, 80 и 443
```

Домен покупать не обязательно. Android-приложение умеет использовать публичный IP с
сертификатом либо бесплатное имя DuckDNS.

## Ресурсы

| Ресурс | Минимум для теста | Рекомендуется для постоянной работы |
| --- | --- | --- |
| CPU | 1 vCPU | 1–2 vCPU |
| RAM | 256 MiB | 512 MiB–1 GiB |
| Disk | около 1 GiB свободно | 5 GiB+ |
| Канал | достаточный для одного сеанса | без жёсткого ограничения трафика |

Relay не перекодирует и не сжимает фото, голосовые сообщения или видео. Весь Telegram-трафик
проходит через VPS, поэтому расход канала примерно соответствует фактическому трафику устройств.
Для многих пользователей или больших media transfers выбирайте больше RAM, CPU и bandwidth и
контролируйте session limits.

## Linux и архитектуры

Серверный binary не требует CGO и выпускается для:

```text
amd64, 386, arm64, armv7, armv6, armv5,
riscv64, ppc64, ppc64le, s390x, loong64,
mips, mipsle, mips64, mips64le
```

Автонастройка Android определяет архитектуру через `uname -m`.

Поддерживаемые package managers:

```text
apt, dnf, microdnf, yum, zypper, apk, pacman, xbps, Portage/emerge
```

Поддерживаемые init-варианты:

```text
systemd, OpenRC, runit, SysV init, portable init-script fallback
```

Это покрывает Debian/Ubuntu, RHEL/Fedora/Alma/Rocky, openSUSE/SLES, Alpine, Arch, Void,
Gentoo-подобные и многие другие Linux-системы. Для редкой системы, где мастер не нашёл
пакетный менеджер или способ автозапуска, используйте [ручную установку](INSTALL.md).

## SSH

Автонастройке нужны:

- IP/host VPS;
- SSH port;
- пользователь;
- пароль;
- root-доступ либо passwordless sudo.

При первом подключении Android показывает тип SSH host key и SHA-256 fingerprint. Сверьте его
с панелью хостинга/консолью VPS. Изменившийся key блокирует повторное подключение до явного
сброса пользователем.

Для новичка проще отдельный чистый VPS. Мастер умеет безопасно добавлять маршрут к известному
nginx/Caddy/Apache, но намеренно останавливается, если не может доказать, что не перезапишет
существующий сайт.

## Сеть и firewall

### Входящие соединения

| Порт | Зачем |
| --- | --- |
| SSH port, обычно TCP 22 | audit, установка и обновление из Android |
| TCP 80 | HTTP-01 проверка и продление сертификата |
| TCP 443 | HTTPS/WebSocket клиентов Relay |

Внутренний listener `127.0.0.1:18080` не нужно открывать в интернет. При Docker Caddy мастер
может выбрать адрес bridge, но firewall должен ограничивать его локальной инфраструктурой.

### Исходящие соединения

VPS должен разрешать:

- DNS;
- HTTPS к GitHub Releases и центру сертификации во время установки/обновления;
- TCP к разрешённым Telegram DC/портам из topology;
- необязательный GeoIP endpoint, если `admin.geoIpUrl` не пуст.

Если провайдер фильтрует Telegram DC на исходящем канале, сам Relay не сможет исправить это.

## Публичный адрес и HTTPS

Выберите один вариант:

1. **Публичный IP** — приложение выпускает поддерживаемый IP-сертификат и использует `443`.
2. **DuckDNS** — бесплатное имя; Android сам обновляет запись и настраивает сертификат.
3. **Свой домен/поддомен** — его A/AAAA-запись должна указывать на публичный IP VPS. Домен не
   обязан уже присутствовать в конфигурации сервера.

VPS за CGNAT без входящего публичного адреса не подходит. При использовании облачного firewall
откройте порты и в панели провайдера, и в firewall операционной системы.

## Чек-лист перед автонастройкой

- [ ] VPS загружается и доступен по SSH.
- [ ] Известен root/passwordless-sudo пользователь и пароль.
- [ ] TCP 80 и 443 не закрыты панелью хостинга.
- [ ] Есть публичный IP.
- [ ] Если выбран свой домен, A/AAAA уже указывает на VPS.
- [ ] На диске есть свободное место, время и DNS сервера корректны.
- [ ] Создан backup важных сайтов, если VPS уже используется.
